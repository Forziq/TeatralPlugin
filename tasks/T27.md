# T27 Emote list, cooldowns and sounds
size: M | who: sonnet-builder | hard: no | deps: T26

Phase 3 starts here: emotes done properly. The MVP "no GUI, nothing extra" rule no longer applies to emotes.

## Goal
Adding an emote means adding its animation and one entry in a list, nothing else. Emotes get a cooldown and an optional sound.

## Steps
1. Read docs/notes/bettermodel.md and docs/notes/models.md (player model section).
2. `EmoteType` enum (or a hard-coded list): id, animation name, play once or loop until cancelled, sound key (nullable), icon item for the menu in T31, English and Russian names in the lang files (`emote.name.<id>`).
3. Entries now: `wave` (once, `emote_whoosh`). Add `salute`, `clap`, `cheer`, `bow`, `point`, `facepalm`, `dance`, `sit` as entries flagged "not animated yet", so `/emote` only offers ones whose animation exists in the loaded model (check through `BetterModelHook`).
4. Cooldown: 3 s per player between emote starts, hard-coded. Translated message with the plural seconds form.
5. Sound: play the emote's sound at the player for everyone within 16 blocks when it starts. Existing sounds only (`emote_whoosh`, `emote_clap`, `emote_cheer`); no new ElevenLabs runs.
6. Move `EmoteService` and `EmoteCommand` onto the list. `/emote <id>` and tab completion come from it.
7. Unit tests for the cooldown and the "which emotes are available" filter.
