# T03 Build and test the dashboard
size: M | who: sonnet-builder | hard: no | deps: T02

## Goal
A simple local web page at http://localhost:4321 where Egor can watch, live, what every agent is doing. `/dashboard on` starts it and opens the browser; `/dashboard off` stops it. Node only, no npm packages.

## What already exists (written during setup, don't rewrite unless broken)
- `.claude/hooks/log-event.mjs`: every hook event (tool calls, subagent start/stop, prompts, stop) is appended as one JSON line to `.claude/dashboard/events.jsonl`. Fields: `t` (ms), `ev`, `agent` (from hook input `agent_type` when present, else `null`), `sid`, `tool`, `text`.
- `.claude/dashboard/status.mjs <agent> "<text>"`: agents write their own plain-English status as `ev: "status"`.
- `.claude/commands/dashboard.md`: calls `node .claude/dashboard/ctl.mjs on|off|status`.
- `progress.md` table format: `id|size|who|deps|status|title`.

## Build
1. `.claude/dashboard/server.mjs` (Node `http`, port 4321, bind 127.0.0.1):
   - `GET /` serves `index.html`. `GET /api/state` returns JSON built from the last ~2000 lines of events.jsonl plus progress.md.
   - Work out who did each event: use `agent` when set. When it's null, keep a stack: a PreToolUse for the `Agent`/`Task` tool pushes its `subagent_type`, the matching PostToolUse or a SubagentStop pops it; events in between belong to the top of the stack, otherwise `main`.
   - Per agent (main, opus-deep, sonnet-builder, sonnet-tester, haiku-scout): latest status line, whether it's active (event in the last 90 s and not stopped), current tool, last 8 actions as short readable lines ("Editing src/.../EmoteCommand.java", "Running ./gradlew test", "Looking up BetterModel docs"), time since last activity.
   - From progress.md: the `now:` line, the current task row, the next three todo rows, done count / total, gate states, blockers.
   - Trim events.jsonl to the last 3000 lines when it passes 5 MB.
2. `.claude/dashboard/index.html`: one file, inline CSS and JS, polls `/api/state` every 1.5 s. Layout: header with project name, current task and progress bar; one card per agent (active ones highlighted, idle ones dimmed); a task list column; a combined activity feed. Clean, readable, light and dark mode via `prefers-color-scheme`. Follow the design-taste-frontend skill so it doesn't look generic, but keep it simple.
3. `.claude/dashboard/ctl.mjs`:
   - `on`: if already running (pid file + process alive, or port answers), say so. Otherwise spawn `server.mjs` detached with `stdio: 'ignore'`, `unref()`, write `server.pid`, wait until the port answers, run `open http://localhost:4321`, print the URL.
   - `off`: kill the pid, remove the pid file, print "Dashboard stopped".
   - `status`: running or not.
   The server must survive `/clear` and the Claude Code session ending.

## Test (sonnet-tester)
- Start it with `ctl.mjs on`, `curl -s localhost:4321/api/state` returns valid JSON with all five agents.
- Append fake events (a status line for haiku-scout, a PreToolUse Agent call for sonnet-builder followed by an Edit) and check they're attributed correctly.
- `ctl.mjs off` frees the port. Running `on` twice doesn't start two servers.
- A small `node --test` file in `.claude/dashboard/test/` covers the attribution logic and the progress.md parser.

## Done when
Egor can type `/dashboard on`, see the page with this task shown as current, and `/dashboard off` stops it.
